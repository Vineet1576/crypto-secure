Why `crypto-secure`?

HTTPS protects the network, but not the data inside your app. This library encrypts requests and responses so your app data stays private end to end.

ThreatHTTPS Protectioncrypto-secure Protection
TLS termination at load balancer❌ plaintext inside your network✅ end-to-end encrypted
Cloud provider / hosting access❌ can read your data✅ only your keys can decrypt
Man-in-the-middle at proxy layer❌ TLS is terminated✅ RSA + AES-GCM envelope
Database leak (server-side)❌ logged after decryption✅ never stored in plaintext
Insider access to server memory❌ plaintext in process✅ encrypted until handled

Encrypted Data format

Data is sent in a small envelope with only encrypted fields. The server and client can read the same encrypted format.

{
  "encryptedAESKey": "",
  "delta": "",
  "tag": "",
  "encryptedData": "",
  "aad": ""
}

Encryption flow

1

Turn data into text

Serialize JSON so the data can be compressed and encrypted.

2

Compress it

Use gzip to make the message smaller before encrypting.

3

Encrypt the payload

Use AES-256-GCM to encrypt the compressed data and protect it from tampering.

4

Encrypt the key

Wrap the AES key with RSA-2048 so only the recipient can open it.

Decryption flow

1

Open the envelope

Decode the base64 fields from the JSON message.

2

Unlock the AES key

Decrypt the wrapped AES key using the private RSA key.

3

Decrypt the payload

Use AES-GCM to decrypt the body and verify it hasn’t changed.

4

Restore the original data

Decompress and parse JSON to get the original payload.

Backend usage

Minimal Express setup with automatic payload encryption and decryption.

npm install crypto-secure
const cs = require("crypto-secure");
const keypair = cs.generateKeyPair("./keys");
app.use(express.json());
app.use(cs.middleware({ privateKey: keypair.privateKey }));
app.post("/api/data", (req, res) => {
  console.log(req.body);
  res.json({ received: req.body, ok: true });
});
Production-ready key persistence 
const fs = require("fs");
const cs = require("crypto-secure");

const keyFile = "./keys/server-key.json";
let keypair;
if (fs.existsSync(keyFile)) {
  keypair = JSON.parse(fs.readFileSync(keyFile, "utf8"));
} else {
  keypair = cs.generateKeyPair("./keys");
  fs.writeFileSync(keyFile, JSON.stringify(keypair));
}

app.use(express.json());
app.use(cs.middleware({ privateKey: keypair.privateKey }));

app.get("/.well-known/encryption-key", (req, res) => {
  res.json({ publicKey: keypair.publicKey });
});

Frontend usage

In the browser, this code gets the server key and encrypts all requests automatically.

npm install crypto-secure
import * as cs from "crypto-secure/client";

const serverKey = await cs.fetchServerPublicKey("/.well-known/encryption-key");
const clientKeys = await cs.generateKeyPair();

axios.defaults.headers.common["x-encryption-key"] =
  cs.getClientHeader(clientKeys.publicKey)["x-encryption-key"];

Encrypt a request

Use `cs.encrypt` before sending payloads to the server.

const encrypted = await cs.encrypt(payload, serverKey);
axios.post("/api/data", encrypted);

Decrypt a response

Use `cs.decrypt` to recover the server response using the client private key.

const res = await axios.post("/api/data", payload);
const decrypted = await cs.decrypt(res.data, clientKeys.privateKey);
axios.interceptors.request.use(cs.createAxiosRequestInterceptor(serverKey));
axios.interceptors.response.use(
  ...cs.createAxiosResponseInterceptor(clientKeys.privateKey)
);

With interceptors enabled, encryption becomes fully transparent for requests and responses.

API Reference

Server-side API

  • generateKeyPair(saveTo?) — generate RSA-2048 keys and optionally write PEM files.
  • encrypt(payload, publicKey, aad?) — hybrid encrypt with gzip compression.
  • decrypt(encryptedPayload, privateKey) — decrypt and gunzip payloads.
  • middleware(options) — Express middleware for auto encryption/decryption.

Browser client API

  • generateKeyPair() — browser Web Crypto RSA key generation.
  • fetchServerPublicKey(url) — retrieve server public key and cache it.
  • encrypt(payload, serverPublicKey) — hybrid encrypt requests.
  • decrypt(encryptedPayload, clientPrivateKey) — decrypt responses.

Security details

Symmetric encryption

AES-256-GCM encrypts the message and generates a tag to prove it was not changed.

  • 256-bit key
  • 96-bit IV
  • 128-bit authentication tag

Key wrapping

RSA-OAEP encrypts the AES key so only the intended server or client can open it.

  • 2048-bit RSA key
  • SHA-256 hash
  • MGF1 mask generation

Compression

gzip runs before encryption to reduce message size without weakening security.

  • Better for payloads over 500 bytes
  • Works with text-based JSON

Core security benefits

  • Encrypted data stays private from browser to server.
  • Each request uses a fresh AES key and IV.
  • Message tampering is detected automatically.
  • Optional metadata (AAD) is bound to the cipher text.
What it does not protect against
  • Side-channel attacks such as timing or power analysis.
  • Quantum attacks — RSA-2048 is not post-quantum secure.
  • Compromised private keys can decrypt past traffic.
  • Client-side XSS that exposes decrypted data in the browser.

Architecture overview

Browser and server share a simple protocol: encrypt in the browser, decrypt on the server, then encrypt the response back.

RSA-2048 OAEP SHA-256 AES-256-GCM gzip compression Base64 wire encoding
